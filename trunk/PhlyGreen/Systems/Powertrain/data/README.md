# Engine-deck data and generated artifacts

Everything in this folder is either an **offline generator** (needs pyCycle/OpenMDAO) or a
**fitted artifact** that the package loads at run time (needs only numpy + scipy +
scikit-learn). PhlyGreen never runs a thermodynamic cycle during a design; it reads these.

## Toolchain — and the name trap

The engine decks `import pycycle`, but the package you install is called **`om-pycycle`**.
They are different names for the same thing:

```bash
pip install om-pycycle        # correct
pip install pycycle           # WRONG: unrelated project
conda list pycycle            # finds nothing useful; it is a pip package, not conda-forge
pip show om-pycycle           # this is how to check the version
```

pyCycle is **not** part of OpenMDAO. It is a separate library built on top of it, and it tracks
OpenMDAO's API closely, which is why both are pinned in `requirements-dev.txt`.

### Versions the shipped artifacts were generated with

```
python        3.12.12
om-pycycle    4.4.0      (imports as `pycycle`)
openmdao      3.44.0
cantera       3.2.0      (emission-index maps only)
numpy         2.3.5
scipy         1.16.3
scikit-learn  1.7.2
```

Regenerating with different versions is expected to give slightly different numbers — the decks
are solved with Newton and the results depend on the solver's convergence path. If you
regenerate, re-run the guard checks in `examples/26_turbofan_design.py` and
`validation/a320_reference.py` rather than assuming the map is equivalent.

## Regenerating

```bash
# turbofan: engine map (~45 min, resumable) then the fit (~10 s)
python data/HBTF_turbofan.py
python train_turbofan_surrogate.py

# turbofan emissions: Cantera CRN over the combustor states exported above (~2 min)
cd emissions_pipeline && python build_turbofan_surrogate.py && python validation_plots.py all

# turboshaft equivalents
python data/Single_spool_GT.py
python train_gas_turbine_surrogate.py
```

The turboshaft map (~10 min) accepts a point only if the deck delivered its target shaft power
and closed its gas-generator shaft and nozzle-area balances within 0.1 %. Each (altitude, Mach)
column is solved from full power downwards, warm-started from converged neighbours, with a power
continuation as the last resort; a point that cannot be converged stops the script. The static
column is solved at Mach 0.01, because pyCycle's `FlightConditions` returns NaN at Mach 0 exactly
(the previous map kept 20 static points at the FAR initial guess, and 4 sea-level Mach-0.2 points
stalled short of their target power). `train_gas_turbine_surrogate.py` refuses a map with an
unconverged row.

The turbofan map accepts a point only if the full-throttle point sits at T4_MAX, its thrust
lapse falls with altitude along the Mach column, both points are at the requested Mach and ISA
static pressure, and the part-power point delivers its thrust fraction (`_stale_state_reason`,
`_reject_reason`). Each column gets a fresh problem, every altitude step is taken at full
throttle, and the thrust fraction is lowered in steps of at most 0.1. A point that fails stops
the run (after the converged points are written); the three grid points the deck cannot solve
on the engine's branch are listed in `KNOWN_UNCONVERGED`. The previous map had its 32,500 and
35,000 ft points on a hotter cycle branch (lapse 0.38 at 32,500 ft against 0.32 at 30,000 ft,
T3 802 K) and three PC 0.30 rows whose full-throttle lapse differed from the other fractions.

Two things to know before regenerating the turbofan map:

1. **The sweep is resumable** and writes each point as it converges, so an interrupted run costs
   only the points still missing. `Turbofan_Universal_Map_F00.txt` is read rather than
   re-measured, which keeps the lapse column identical across runs.
2. **`ENVELOPE` is the set that converges, not the set worth having.** The high-Mach columns are
   deliberately split into low and high altitude segments because each entry restarts the
   continuation with fresh guesses — marching M 0.75 up from sea level diverges at 20 000 ft,
   whereas starting a fresh segment there reaches 35 000 ft. Merging those entries silently
   breaks the cruise columns. See the comments on `ENVELOPE` in `HBTF_turbofan.py`.

OpenMDAO writes a `<script>_out/` reports directory next to whatever it runs. Those are
gitignored and safe to delete.
